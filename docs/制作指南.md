# 从比分表到赛事海报

[返回首页与成图展示](../README.md)

这份指南使用杨胖杯的两场九局比赛作为例子。数据、图片与排版分开维护，换比分时保留原模板即可。

## 1. 准备运行环境

安装 Node.js，然后在仓库根目录运行：

```bash
npm install
npx playwright install chromium
npm run maps:audit
```

`maps:audit` 核对仓库内 13 张地图的索引、图片和校验值。Playwright 负责将 HTML 渲染成图片，Sharp 用于图库处理。

渲染器会优先使用 Windows 上的 Chrome/Edge；其他环境可使用已安装的 Playwright Chromium。指定浏览器时，在战报命令末尾加 `--browser "/你的浏览器完整路径"`。均分榜和战报也都支持 `QQSPEED_BROWSER` 环境变量。

## 2. 准备比分 JSON

两队各两名选手，按固定局序填写分数。下面是一局的完整示例：

```json
{
  "title": "2v2个人竞速",
  "subtitle": "杨胖杯 · 单局示例",
  "show_stars": true,
  "teams": [
    {
      "name": "波喵",
      "logo": "../qqspeed-battle-report/assets/bomiao-logo.png",
      "total": 16,
      "players": [
        {"name": "沐瑞", "total": 11, "scores": [11]},
        {"name": "喵帕斯", "total": 5, "scores": [5]}
      ]
    },
    {
      "name": "寒岛",
      "logo": "../qqspeed-battle-report/assets/handao-logo.png",
      "total": 15,
      "players": [
        {"name": "张寒", "total": 9, "scores": [9]},
        {"name": "岛", "total": 6, "scores": [6]}
      ]
    }
  ],
  "rounds": ["端午竞渡"]
}
```

把示例存到 `yangpang/matches/我的比赛.json`，队标相对路径就能直接使用。换到其他目录时，队标路径也要相应调整。

| 字段 | 含义与规则 |
|---|---|
| `teams` | 两支队伍，顺序对应画面左、右 |
| `players` | 每队两人，顺序对应每局卡片的上下位置 |
| `name` | 成图显示名，直接按输入文字绘制 |
| `logo` | 本地图片路径，相对 JSON 文件所在目录解析 |
| `scores` | 按局序填写数字，数组长度与 `rounds` 一致；真实零分填 `0` |
| `total` | 可省略；填写时必须与逐局计算结果相同，否则停止导出 |
| `rounds` | 地图全名或索引中登记的别名，保留重复地图 |
| `show_stars` | 是否显示图库中登记的星级，默认显示 |

当前模板支持 1–12 局；九局版的完整数据见 [波喵 VS 寒岛](../yangpang/matches/波喵VS寒岛.json) 和 [不知豆队 VS 虾头路障](../yangpang/matches/不知豆队VS虾头路障.json)。

调整单局背景裁切时，可把地图字符串改为：

```json
{"map": "心渊", "background_position": "67% 50%"}
```

## 3. 导出战报

```bash
npm run report -- --config "yangpang/matches/我的比赛.json" --out-dir outputs --work-dir work/my-match
```

- `outputs/` 保存高清 PNG 和 JPG；同名文件已存在时自动生成 `-v2` 等新版本。
- `work/my-match/` 保存 HTML、解析后的地图与比分、校验结果。
- 通过 `--library "你的图库目录"` 可以使用另一份兼容的赛道图库。

模板文件为 [report-template.html](../yangpang/qqspeed-battle-report/assets/report-template.html)。字号、背景蒙层、金色比分和卡片间距均在模板 CSS 中调整。战报模板沿用原版的系统中文字体与 Impact 数字；下面的均分榜使用白鸽天行体。

## 4. 制作均分榜

```bash
npm run ranking
```

编辑 [ranking-data.json](../yangpang/average-ranking/ranking-data.json) 中的 `rows` 数组和 `pending` 名单：

```json
{"name": "选手名", "average": 10.56, "rate": 66.67, "total": 95, "games": 9}
```

- `average` 是总分除以场次、保留两位小数的结果。
- `rate` 使用百分数单位，例如 `66.67` 表示 `66.67%`。
- 同均分并列，名次使用 `1、2、3、3、5` 的方式。
- `pending` 保存暂无数据的选手，空白成绩不作为零分参与排名。
- 渲染只读取数据文件，不会覆盖它；`rank` 字段如已存在，会按当前均分重新计算名次。

当前版式支持 1–8 名已参赛选手。`overall` 是可选的总均分校验值，换比赛时应更新该值或删去该字段，由程序计算；超过 8 行需要先调整版式。赛事标题、说明和字体在 [build-ranking.cjs](../yangpang/average-ranking/build-ranking.cjs) 中修改。画面导出为 2160×2880，文件名附时间戳，PNG/JPG 共用同一名称。

## 5. 检查后再发布

渲染器会检查总分、局数、缺图、比分文字和溢出。人工仍应打开成图逐项检查：

1. 队伍左右顺序、队标、选手显示名是否对应。
2. 每局分数、零分、个人总分与队伍总分是否一致。
3. 地图顺序、重复地图和裁切位置是否正确。
4. 长地图名是否完整，缩小到手机宽度后是否清晰。

队标设计可参考 [六支队伍的成品](../README.md#六支队伍与队标)。从队名提取一个明确主体，控制轮廓与细节，保留透明背景，再缩小检查识别度。准确比分和姓名始终由脚本排版绘制。
