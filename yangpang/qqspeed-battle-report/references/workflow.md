# 战报制作与验证

## 输入数据

先转录比分，再作图。渲染器使用UTF-8 JSON；四人的顺序是左队两人、右队两人。每人 `scores` 按局序填写，长度必须与 `rounds` 一致。

```json
{
  "title": "2v2个人竞速",
  "subtitle": "九局战报",
  "teams": [
    {"name":"波喵","logo":"加菲猫队标的绝对路径.png","total":146,"players":[
      {"name":"沐瑞","source_name":"林波","total":90,"scores":[11,11,11,8,10,8,11,11,9]},
      {"name":"喵帕斯","source_name":"mps","total":56,"scores":[5,6,9,8,8,7,0,6,7]}
    ]},
    {"name":"寒岛","logo":"冰雪岛屿队标的绝对路径.png","total":144,"players":[
      {"name":"张寒","total":82,"scores":[9,10,6,11,11,11,7,6,11]},
      {"name":"岛","total":62,"scores":[6,9,7,8,8,9,2,8,5]}
    ]}
  ],
  "rounds":["端午竞渡","雾山五行","心渊","决战！雪山之巅","秋名山","伊甸掠影","流觞曲水","端午竞渡","决战！雪山之巅"]
}
```

- `name` 是成图显示名，`source_name` 仅帮助对应表格，不输出。`total` 可省略以逐局之和计算；提供时必须与计算值一致。
- `logo` 接受本地PNG/JPG路径，相对路径基于配置所在目录。两枚沿用队标保存在技能 `assets/`；复制示例到别处时，把队标路径改为技能内对应文件的绝对路径。
- `rounds` 接受已登记简称；渲染后显示地图全名。需要调整某局裁切时，使用 `{"map":"心渊","background_position":"67% 50%"}`。
- 图库中的 `心愿→心渊`、`流水→流觞曲水` 记录了本次用户确认过的写法；新的模糊截图不能仅靠这些别名推断，仍需结合表格与用户语境核对。
- 比分允许有限数值，脚本不擅自套用排名计分规则。缺项、null、字符串数字、错总分会直接报错。原表中的0必须保留。

## 运行命令

先调用 `load_workspace_dependencies`，使用它返回的Node运行时和包目录；不要从旧聊天复制版本号。示意命令中的 `<技能目录>`、`<包目录>`、`<任务目录>` 应替换成实际绝对路径。

```powershell
node '<技能目录>/scripts/library.cjs' find '端午' '雪山' '五行'
node '<技能目录>/scripts/render-report.cjs' --config '<任务目录>/work/match.json' --out-dir '<任务目录>/outputs' --work-dir '<任务目录>/work/render' --node-modules '<包目录>'
```

默认图库为 `E:/qq飞车地图`，无需每次传入；迁移或测试时才用 `--library` 覆盖。默认3840×2160、支持1–12局；更多局或新画幅应按用户需求调整模板与脚本，不应删局适配。Chrome或Edge可自动定位，也可用 `--browser` 传本地浏览器可执行文件。脚本在本地无界面渲染，不操作用户的浏览器会话。

脚本导出PNG与JPG；已有同名文件时自动追加 `-v2` 等版本。HTML、使用的地图和逐局数据、机器校验结果均保存在 `--work-dir`，便于追溯。

## 地图素材维护

- `catalog.json` 的 `maps` 数组每张地图至少包含 `name`、`aliases`、`original`、`thumbnail`、`source_page`、`source_image`、`source_type`、`sha256`、`status`。
- 图片路径相对图库根目录。官方直发、官方公告转载、社区图鉴转载要按实际来源记录，不把社区网站称为官方站。原始文件保留，后续作图优先用原图。
- 遇到新图：先核实它属于QQ飞车手游，保存官方场景美术图或真实赛道预览；不要存路线示意图、车手头像、活动头图或广告图。用 `view_image` 检查名称与场景，再加入索引。
- 新增记录需保留来源URL、原文件SHA-256；完成画面核对后设 `status: verified`，同步 `expected_count`。
- 仅更新素材后执行 `prepare-library.cjs --library 'E:/qq飞车地图' --work-dir '<任务目录>/work/map-review' --node-modules '<包目录>'`，生成同名缩略图和总览，再运行 `library.cjs audit`。不要每次调用时重新下载45张图。

## 成图检查

机器检查包括总分一致、每人局数一致、局序与重复地图保留、所有图片成功解码、中文名字无截断、渲染格数正确、分数文字与配置逐项一致。

还要实际查看PNG：顶部头像/队标及姓名的对应关系、中央左右比分、卡片顺序、背景是否与地图对应、+0与小分数、长名字/地图名，以及文字在原尺寸和缩小预览中的可读性。若背景裁切不理想，调整该局的 `background_position`；若有白色线路覆盖，优先改用同地图的已核对场景图，不生成或修补游戏场景。
